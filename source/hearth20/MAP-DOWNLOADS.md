# Background maps and token-bound views

The DM's active_scene is an editor selection. Player projections and board requests resolve the player's chosen owned token (campaign viewpoints, then the recorded character or legacy assigned hero) and its deployed scene. A missing, stored, decorative or non-token-layer viewpoint has no board view. Cover remains a campaign-wide override. D&D Beyond sheets/chat remain available while waiting; character senses are still outside this fork's common environmental-lighting model.

Authenticated peers negotiate background-maps-v1. On joining or importing maps, one bounded worker prepares fog-redacted PNGs and independent decorative/foreground PNGs for every campaign scene. Only encrypted files and opaque identifiers are prefetched. Unplaced characters receive no decryption keys. Live projections release the keys solely for their currently authorized map and visible foreground assets. No future actor state, GM notes, private sheets or stat blocks are prefetched. Authoritative fog redaction and normal per-recipient filtering remain in place.

Live state uses the control channel; bulk map frames use reliable channel 2. Per-file offsets survive scene/editor switches and map cover. A token's new destination can take priority while the prior file retains its offset. Downloads are verified by SHA-256 before use. Decrypted images use a bounded 64 MiB memory cache; connection-scoped files use a bounded 2 GiB disk cache and are removed on disconnect. They are not promised as a persistent cache across game restarts. Shared foreground images are sent once per connection.

The non-interactive map-edge bar shows ready map-file count, real received/total bytes and measured MB/s. Preparing files is separate from receiving them. The total can increase when the DM imports more content; that adds work without resetting previously received bytes.

The 0.3.17 high-maximum-only Steam rate assumption was incorrect. Version 0.3.18 applies matched chosen rates to each connection and adjusts them from observed traffic, delivery quality and latency. See AUTOSAVE-AND-TRANSFER-RATES.md for the corrected analysis, bounds and verification limits. The bulk sender retains fair time/queue limits; background map progress is independent of the live scene. Actual cross-network Steam speed still requires measurement.

Changing masks/artwork creates a new content identity; tab selection does not. Already cached pages do not transfer again when a hero moves between them. Midflight cover/stow clears the live view immediately and cannot be undone by a late file completion. Player draws, movement, pings and measurement previews target their token's scene, including when the DM is elsewhere. New draw requests carry their viewed scene identifier so a request from an old page cannot accidentally edit the token's next map.

Verification stays scoped to maps, tokens, related UI and updater handling. The five-process fixture covers one host/four players, independent scenes, an inventory-only player, shared/secret foreground images, partial resume, repeated DM tab changes, midflight cover, aggregate progress, cached transfer, off-map movement/drawing/pings and cleanup. No fresh real Steam account test or target-hardware frame-rate claim is implied.
